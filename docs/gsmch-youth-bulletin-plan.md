# 선한목자 젊은이교회 모바일 주보 기획서

작성일: 2026년 10월 25일  
프로젝트명: `gsmch-youth-bulletin`  
상태: 프로토타입 범위 확정안 + 후속 계정·행사 신청 확장안

## 1. 목적

성도는 로그인 없이 휴대전화로 최신 예배 주보를 읽는다. 운영자는 로그인한 관리자 화면에서 매주 바뀌는 내용만 입력해 발행한다. 종이 주보 전체를 옮기기보다 예배에 필요한 핵심 내용으로 시작한다.

공개 주소 `https://domain.com/`은 매주 그대로 유지한다. 이 주소로 만든 QR 코드를 인쇄해 두면 새 주보가 발행될 때마다 같은 QR로 최신 주보를 볼 수 있다. 하루 약 1,000회 방문을 예상하고 모바일 로딩 속도와 PWA의 오프라인 읽기를 설계에 포함한다.

## 2. 프로토타입에 들어갈 내용

| 구역 | 표시 내용 | 입력 방식 |
| --- | --- | --- |
| 표지 | 예배 날짜, 이번 주 주제, 대표 이미지 | 날짜·주제는 매주 입력. 이미지는 선택 |
| 예배 순서 | 순서명과 담당자 | 지난주 목록을 복제해 수정 |
| 설교 | 제목, 성경 본문, 설교자 | 매주 입력 |
| 홍보 | 짧은 홍보 카드 최대 3개 | 매주 입력. 제목·설명은 필수, 링크는 선택 |
| 교회 안내 | 예배·모임 시간, 교회 소개, 비전, 오시는 길 | 고정 정보로 등록하고 변경 시 수정 |

홍보 카드의 **화면 예시**는 다음 세 가지다. 아래 문구는 디자인과 입력 흐름을 확인하기 위한 샘플이며 실제 일정·담당자·연락처를 뜻하지 않는다.

1. **새가족 안내:** 처음 오신 분을 위한 예배 및 모임 안내. 버튼 예시: `안내 보기`.
2. **소그룹 모임:** 함께 말씀을 나누는 모임 소개. 버튼 예시: `모임 문의`.
3. **봉사 참여:** 예배와 공동체를 함께 섬길 분을 위한 안내. 버튼 예시: `참여 문의`.

홍보 카드는 0~3개까지 등록할 수 있다. 링크가 없으면 버튼을 표시하지 않는다. 대표 이미지가 없으면 이미지 영역을 비워 두는 대신 날짜와 주제가 중심이 되는 텍스트 표지로 보여 준다.

교우 소식, 성경 통독표, 설교 노트, 헌금 안내, 기간 자동 종료 공고, 통계, 알림, PDF 제작은 이번 프로토타입에 포함하지 않는다.

## 3. 방문자 화면과 주소

| 주소 예시 | 기능 |
| --- | --- |
| `https://domain.com/` | 현재 발행된 최신 주보. 인쇄 QR의 대상 |
| `https://domain.com/bulletins/2026-10-18` | 해당 날짜 주보의 고정 주소 |
| `https://domain.com/archive` | 이전에 발행한 주보 목록 |
| `https://domain.com/admin` | 관리자 로그인 및 편집 |

최신 주보는 날짜별 주소로 이동시키지 않고 `/`에서 직접 보여 준다. 날짜별 링크는 발행 후 유지한다. 새 주보를 미리 작성해도 **발행 버튼을 누르기 전까지** 공개 주소에는 기존 주보가 보인다. 아직 발행된 주보가 없으면 교회명과 준비 중 안내를 표시한다.

인터넷에 연결된 상태에서 주보를 한 번 열면 최신 주보의 텍스트와 대표 이미지를 기기에 저장해, 이후 연결이 끊겨도 읽을 수 있게 한다. 오프라인 화면에는 **저장된 주보의 날짜**를 표시한다. 처음 방문하거나 기기 저장소가 지워진 경우에는 오프라인에서 내용을 볼 수 없으며, 관리자 편집과 영상 오프라인 저장은 포함하지 않는다.

모바일 화면은 **표지 → 예배 순서 → 설교 → 홍보 → 교회 안내 → 지난 주보 링크** 순으로 구성한다. 교회 안내는 길게 펼친 문단보다 항목별 카드로 보여 준다. 오시는 길은 주소 텍스트와 지도 링크를 제공한다.

## 4. 관리자 운영 방식

관리자는 `domain.com/admin`에서 교회가 승인한 계정으로 로그인한다. 화면은 **주보 목록·편집**, **교회 안내 편집** 두 영역으로 시작한다.

매주 운영 순서는 다음과 같다.

1. **새 주보 만들기**를 누르면 마지막 주보의 예배 순서 틀만 복제된다. 날짜·주제·설교·홍보 내용은 새로 입력한다.
2. 대표 이미지는 업로드하거나 생략한다. 이미지를 제거하면 텍스트 표지로 미리 보인다.
3. 모바일 미리보기에서 내용을 확인하고 **발행**한다. 공개 주소가 새 주보로 바뀌며 이전 주보는 보관된다.
4. 오탈자는 해당 주보를 다시 편집해 저장한다. 프로토타입에서는 별도의 승인 단계나 버전 되돌리기를 만들지 않는다.

발행 전에는 날짜·주제·설교 정보·예배 담당자·홍보 링크를 확인한다. 교회 안내는 주별 주보와 별도로 관리하므로 매주 다시 입력하지 않는다. 지난 주보 화면에도 현재의 교회 안내를 표시하며, 날짜별 주보 자체의 내용은 유지한다.

## 5. 디자인 원칙

따뜻한 미색 바탕과 짙은 남색 또는 먹색 글자, 절제된 금색 포인트를 사용한다. 종이 주보의 친근한 분위기를 참고하되 좁은 모바일 화면에서는 표 대신 세로 목록과 카드로 정리한다. 이미지가 있는 주와 없는 주 모두 완성된 표지로 보이게 한다.

본문은 휴대전화에서 편안히 읽을 수 있는 크기와 줄 간격을 사용한다. 버튼은 누르기 쉬운 크기로 만들고, 대표 이미지에는 대체 텍스트를 입력한다. 카카오톡 내부 브라우저에서도 읽기와 링크 이동을 확인한다.

## 6. 프로토타입 완료 기준

- 운영자가 코드 수정 없이 주보를 작성·미리보기·발행할 수 있다.
- 대표 이미지를 넣거나 빼도 표지가 자연스럽게 표시된다.
- 주보를 새로 발행하면 같은 QR 주소에서 최신 주보를 볼 수 있다.
- 지난 주보 목록과 날짜별 고정 링크로 이전 내용을 볼 수 있다.
- 로그인하지 않은 사람은 관리자 화면과 초안에 접근할 수 없다.
- 교회 안내를 한 번 수정하면 공개 화면의 안내가 갱신된다.
- 온라인에서 한 번 연 최신 주보는 오프라인에서도 읽을 수 있고, 저장된 주보의 날짜가 표시된다.

## 7. 제작 전에 채울 실제 정보

프로토타입에는 샘플 홍보 문구를 넣을 수 있지만 공개 전에는 실제 **예배·모임 시간, 교회 소개와 비전, 주소·지도 링크, 관리자 이메일, 도메인**이 필요하다. 종이 주보 사진의 정보는 현재 운영 정보로 자동 채택하지 않는다.

## 8. 후속 확장: 일반 계정과 행사 신청

이 절은 **추후 구현할 기능**이다. 위 프로토타입의 공개 조회·주보 발행 범위나 완료 기준에는 넣지 않는다. 다만 지금부터 계정 식별자와 행사 데이터가 웹 전용 구조에 묶이지 않게 설계한다.

| 이용 상태 | 주보·지난 주보 조회 | 행사 신청·내 신청 조회 | 관리자 편집 |
| --- | --- | --- | --- |
| 비로그인 방문자 | 가능 | 신청 버튼을 누르면 로그인 안내 | 불가 |
| 로그인한 일반 계정 | 가능 | 가능 | 불가 |
| 승인된 관리자 계정 | 가능 | 가능 | 가능 |

로그인 여부에 따라 **주보 본문이 달라지지 않는다.** 발행된 주보와 행사 신청 버튼은 누구나 같은 주소에서 볼 수 있다. 비로그인 방문자가 버튼을 누르면 로그인을 거치고, 로그인한 사람에게는 `내 신청` 상태도 보여 준다. 관리자는 별도 비밀번호 체계를 만들지 않고 같은 인증 기반에서 교회가 승인한 사용자 ID에만 관리자 권한을 준다.

신청 흐름은 다음과 같다.

1. 운영자가 홍보 카드에 행사와 `신청하기` 버튼을 연결한다. 방문자는 행사명, 날짜, 신청 마감, 필요한 정보와 개인정보 이용 안내를 **버튼을 누르기 전에** 본다.
2. 방문자가 `신청하기`를 누른다. 로그인 중이면 바로 신청을 처리한다. 비로그인이라면 어떤 행사에 신청하려 했는지만 잠시 보관하고 로그인 화면으로 간다.
3. 로그인에 성공하면 원래 누른 **해당 행사 한 건만 자동 접수**하고 `신청 완료` 또는 `이미 신청함`을 보여 준다. 단순히 주보를 열거나 일반 로그인 버튼으로 들어온 경우에는 아무 행사에도 신청하지 않는다.
4. 마감·정원 초과·네트워크 오류라면 접수하지 않고 이유를 보여 준다. 중복 탭이나 로그인 화면 재진입으로 신청이 두 번 생성되지 않아야 한다.

이름 외에 추가 답변, 보호자 동의, 참가비 결제 등이 필요한 행사는 자동 접수 대신 **로그인 후 입력·확인 화면**으로 보낸다. 취소 가능 여부와 정원·대기자 운영은 실제 첫 행사에 맞춰 결정한다. 신청 내역은 주보 오프라인 저장 대상에서 제외하고, 인터넷이 없으면 신청 버튼에 온라인 연결 안내를 표시한다.

## 9. 앱 확장을 위한 제품 원칙

향후 모바일 앱도 같은 주보·행사 데이터와 같은 계정을 사용한다. 사용자가 웹에서 신청한 행사는 앱의 `내 신청`에도 나타나야 한다. 웹사이트 주소와 인쇄 QR은 계속 웹의 최신 주보로 연결되며 앱 설치를 강요하지 않는다. 웹과 앱의 화면 구현은 달라도 신청 규칙과 관리자 권한 판단은 공통 백엔드에서 처리한다.

일반 계정 로그인 방식은 **실제 교인들이 주로 쓰는 제공자 한 가지로 먼저 시작**하는 것이 운영이 간단하다. Google과 Kakao를 동시에 열면 한 사람이 서로 다른 계정으로 가입할 가능성이 있으므로, 두 번째 제공자를 추가하기 전에 계정 연결·중복 신청 처리 방침을 정한다. 이메일 비밀번호 로그인과 자체 SMTP는 필수로 두지 않는다.
